# tmux pane controls — 2026-10-14

The Split H/V toolbar and keyboard actions now use tmux for SSH terminals
opened with automatic tmux attachment. They do not open another SSH connection
or modify ShellDeck's native pane tree. Local and plain SSH terminal behavior
is retained. The managed toolbar also exposes next-pane focus, layout cycling,
and tmux pane zoom; font zoom remains a separate control.

The interactive SSH channel starts tmux through an exec request. A private,
bounded startup header identifies that channel's PTY and preserves following
terminal bytes. A typed controller uses separate exec channels on the same SSH
connection. Each operation resolves the attached client's current session and
active pane. Split panes inherit the target pane's current directory.
Detached-client errors do not trigger a fallback or retry. The new controls
do not kill panes or the processes running in them.

Automated checks: `cargo test --locked -p shelldeck-ssh -p shelldeck-terminal --lib`
with the repository's pinned toolchain, `PKG_CONFIG_PATH`, debug information
disabled, and incremental compilation disabled, with test threads set to 1
to avoid the existing ephemeral-port fixture race. SSH: 51 passed, 1 pre-existing
ignored live test. Terminal: 94 passed. The suite includes startup framing,
invalid identities, failure propagation, and control actions leaving the
foreground-input channel empty. An in-memory SSH server also verifies that
output EOF before exit status retains both success and failure statuses.
The existing terminal-link regressions remain covered.
`cargo build --locked -p shelldeck` and `cargo fmt --all -- --check` also pass.

A live fixture executes commands generated by the production Rust
`TmuxClient::command` method over the project SSH configuration. The same checks
also run through `TmuxClient::apply` and ShellDeck's native `SshClient`, including
exit-status collection on its control channel. These native checks exposed
OpenSSH sending EOF before exit status; `SshSession::exec` now waits for channel
close so successful actions do not display false errors. The fixture creates two
temporary tmux sessions and two real PTY clients, runs idle processes in a
directory containing spaces and an apostrophe, and removes only its own
sessions/directories afterward. No model prompts are sent and no existing
server panes are changed.

Verified on `activ2` with tmux 3.4 and `activ1` with tmux 3.0a:

- Side-by-side and top/bottom splits produce server panes and inherit cwd.
- Actions for each client stay in its own session.
- Next-pane focus moves; layout cycling preserves all panes.
- Pane zoom toggles on and restores normally.
- Switching to another window causes the next split to target that window
  and inherit its different directory.
- A detached client's split fails without changing any pane count or ID.
- Reattachment preserves every pane ID and the server's layout.

Native pointer automation is unavailable in this session. Toolbar rendering
uses the existing button/icon helpers and localized French/English tooltips;
the live tests exercise the same command generator, native SSH execution and
tmux behavior. Native startup, automatic SSH attachment and graceful restart
were verified during local installation. The final build was installed at
`~/.shelldeck/bin/shelldeck` and restarted with the user's approval; all three
existing `activ2/main` pane IDs remained unchanged.
